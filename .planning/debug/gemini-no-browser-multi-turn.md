## Resolution

root_cause: "Gemini web frontend requires per-turn Web Attestation / botguard tokens in inner_req_list slots 3/4. These tokens are generated by client-side JS that is loaded dynamically and signed over the serialized request. A pure HTTP client can perform the first turn and extract conversation state, but every subsequent turn fails with BardErrorInfo [1096] unless slots 3/4 contain valid browser-generated tokens. No static lightweight source for these tokens exists in /app bootstrap, WIZ_global_data, or batchexecute."
fix: "No production code change. Added two diagnostic binaries (src/bin/multi_turn_no_browser.rs and src/bin/multi_turn_browser_token.rs) and improved extract_conversation_state to handle the wrapped WIZ response format. The browser-attestation simulation was also made more resilient with a wait for the Angular-rendered input."
verification: "cargo test --lib passes (81 tests). cargo build --bin multi_turn_no_browser and cargo build --features browser-attestation succeed. Harness captures saved to /tmp/opencode/captures/multi_turn_no_browser/."
